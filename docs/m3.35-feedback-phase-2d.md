# M3.35 Phase 2D self-hosted owner authentication

Better Auth 1.7.27 is pinned, MIT-licensed and runs in the existing Next.js 16 Node process against the dedicated MySQL/MariaDB staging schema. It requires no hosted authentication service, trial or subscription. The existing Hostinger mailbox supplies the one-time owner verification email and the separate feedback worker continues to use it. [Better Auth Next.js support](https://better-auth.com/docs/integrations/next) · [Better Auth two-factor authentication](https://better-auth.com/docs/plugins/2fa)

## Staging setup

1. Confirm hPanel is targeting the existing private staging website and `u926782974_crefb_stage`, that a recoverable backup exists, and that the staging-only launcher has Node 24. Review migration 003 using separate migration access. Keep the previously applied migration history intact. The app account should have only scoped read/write access to the necessary tables. Backups contain sensitive session and credential material and need restricted access and encryption.
2. Preserve the existing staging-only gate and verified client-address header. In the private environment set `FEEDBACK_AUTH_SECRET` to a fresh random 32-byte hex value independent of `FEEDBACK_HMAC_KEY`, and configure `FEEDBACK_OWNER_INBOX` and `FEEDBACK_SMTP_PASSWORD` through Hostinger secrets. Existing Auth0 environment settings are unused and may be removed from staging after verification. Do not add logs for cookies, request bodies, owner searches, passwords or account material.
3. Run the attended command once from a private, unrecorded staging terminal with `CRE_FEEDBACK_OWNER_BOOTSTRAP=enabled` scoped to that process only. The command is `node --conditions=react-server --import tsx scripts/provision-feedback-owner.ts`. Confirm the owner can read the private inbox, enter the one-time code, choose a unique password, and enroll a TOTP authenticator. Store the single-use recovery codes offline. The terminal displays the TOTP enrollment URI and codes only for the attending operator. Never copy them into logs or GitHub.
4. Verify the staging owner sign-in at `/owner/feedback`. Test no signup path, password-only denial, TOTP, one recovery code and reuse denial, session expiry, sign-out, and unauthorized access. Confirm the server never retains a trusted-device cookie. Only then continue the existing synthetic submission, restart, SMTP recovery and database restore checks. Public feedback remains gated.

## Authorization and recovery

The application exposes only selected POST endpoints. It enforces the configured same origin and a verified client address, and uses transaction-backed rate limits with separate owner and feedback buckets. The Better Auth engine checks credentials and factors. The dashboard additionally requires the bound user ID, verified email, enrolled MFA, a database session with explicit second-factor proof, and a 15-minute expiry. Sessions do not roll or cache in cookies. Session cookies are signed, Secure, HttpOnly and same-site. The database holds opaque short-lived session tokens and encrypted TOTP secrets and backup codes. Revoke sessions server-side and restrict database and backup access.

A recovery code is a second factor and still requires the password. If a password or all factor recovery material is lost, use a separately authorised, attended operator recovery. Verify the owner's identity and mailbox again, disable staging auth traffic, revoke all owner sessions, back up the authentication tables and review reset of only the 003 schema with migration access. Provision afresh with a new password, authenticator and codes. Keep feedback data intact. If bootstrap aborts after account creation but before owner binding, it refuses a second run. Review auth rows and perform an explicitly authorised rollback or restore before retrying.

Local integration tests use a synthetic owner and SQLite's in-memory database to exercise the actual SDK. This does not verify MariaDB, live Hostinger SMTP, the private ingress header, or staging restart and restore. Test those separately before activation.
